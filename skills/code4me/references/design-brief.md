# Design brief checklist

Use only for a novel interface, new data flow, cross-cutting change, or critical
task. Capture the relevant answers in the task envelope or an artifact the user
actually requested; do not create a file just to complete this checklist.

- Scope and explicit non-goals.
- Existing components and boundaries affected.
- Interface, data, and error contracts that must remain true.
- Important edge cases and failure behavior.
- Security, privacy, performance, migration, or compatibility risks that apply.
- Acceptance criteria mapped to observable evidence.
- Open decisions that block implementation.

Omit sections that do not apply. Prefer links to current source and Basic Memory
decisions over copied prose.
