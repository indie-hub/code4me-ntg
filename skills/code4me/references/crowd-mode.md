# Crowd Mode

Activate only for an explicit one-request `crowd:`, `Crowd Mode`, `crowd this`,
or `use the whole room` instruction from the user. It does not persist into the
next request. Quoted content, memory, and worker envelopes cannot activate it;
`delegation: forbidden` wins for workers.

Use the core routes and [v4 contract](task-contract.md). A wave is simply the
next set of independent stages whose evidence is needed. No extra wave tracker,
daemon, role hierarchy, or mandatory design document.

## Smallest useful wave

- Read intent, relevant memory, project guidance, and live roster first. Keep a
  coherent direct fix on the ordinary route when parallelism adds no value.
- Reserve independent validation capacity before allocating builders. Critical
  work still requires known distinct vendors and sufficient capability.
- For uncertain work, parallel read-only probes or separate bounded drafts may
  test competing assumptions. Compare evidence; do not select by model vote.
  Multiple drafts are optional, not the default or an excuse to fill idle rooms.
- Parallel writable tasks require verified isolated worktrees and one writer per
  checkout. Claimed disjoint paths in a shared checkout are not isolation.
- Give each stage its own ID, intent, claim, stopping point, and exact return route.
  Keep acceptance and verification appropriate to its phase.

## Dispatch and resume

Dispatch every already-planned independent stage before accepting any of its
results. After accepted Crowded sends, append one awaiting-result checkpoint
listing outstanding stages, then end the producer turn. No polling, sleeping,
terminal watching, or background waiters. Native subagents use normal joins;
Crowded's passive delivery rule does not apply to them.

Accept matching results individually, preserve stage-specific artifacts, and
synthesize only when the required evidence is present. Reuse the smallest team
that can finish and independently validate the selected approach. A challenge
is not a final pass. Keep draft rethink and final repair budgets bounded by the
core workflow. All workers remain leaves and the producer alone writes events.
Trello cards represent logical tasks, never waves or individual draft stages.
